# Сайт MiMiSmart — правила работы

Файл для агентов, читающих `AGENTS.md` (Codex и совместимые). Тот же свод, что
в `CLAUDE.md`, — держать их согласованными обязательно: разойдутся, и два человека
будут работать по разным правилам.

Начинать с `README.md` (как запустить) и `docs/ПЕРЕДАЧА.md` (состояние дел, грабли,
что заблокировано).

## Что за проект

Сайт компании, которая разрабатывает, производит и монтирует системы «умный дом».
Заменит пять устаревших доменов. 139 страниц, статическая сборка Next.js.

Проектируется **под ИИ-поиск**, а не под классическое SEO. Точки входа — Google SGE,
Яндекс Нейро, ChatGPT. Отсюда всё устройство: у каждого ответа свой адрес, заголовок
в форме вопроса, прямой ответ первым абзацем, весь текст в HTML до исполнения
скриптов.

## Три правила, нарушение которых стоит дороже всего

1. **Текст правится в прототипе** `tz-site/prototype/mimismart-v5.html`, а не в
   `site/`. Оттуда его достаёт `npm run content`. Правка прямо в `site/` живёт до
   следующей сборки и потом молча пропадает.

2. **Ни одной выдуманной цифры.** Цены, кейсы, сроки, количества — только данные
   клиента. Непроверенное помечается `⚠️` прямо в тексте и попадает в собираемый
   список `site-foundation/fill-list.md`. Убрать пометку, не получив данные, нельзя:
   неподтверждённое уйдёт машине как факт.

3. **Приёмка обязана уметь падать.** Добавили условие — добавьте мутацию в
   `tools/mutate.mjs`, иначе условие может оказаться нерабочим и никто не заметит.
   Так уже было: гейты мерили контейнер вместо переполняющего его содержимого
   и считали класс, который со страниц исчез.

## Команды

```bash
npm run setup     # зависимости и Chromium для приёмки
npm run doctor    # что стоит, чего не хватает
npm run dev       # localhost:3000
npm run content   # перечитать прототип
npm run build     # выгрузка → сборка → чистка, результат в site/out
npm run check     # язык, приёмка прототипа, приёмка собранного сайта
```

Перед коммитом гонять `npm run check`. Приёмок две, потому что предмета два:
прототип и собранный сайт живут параллельно, пока перенос содержимого не закончен.

## Стандарт языка

Весь текст — сайт, ТЗ, коммиты, документы — проходит `npm run check:lang`. Он падает
на конкретных вещах, а не на вкусовщине:

- декларации вместо фактов («инновационный», «уникальный», «современное решение»);
- превосходство о себе без критерия — это ещё и статья 14.2 ФЗ-135;
- пустые зачины («в современном мире», «не секрет, что»);
- числа в документах, разошедшиеся с прототипом.

Пишем: активный залог, конкретика вместо абстракций, разный ритм предложений,
читатель в сцене. Без оборотов «не X, а Y», кроме позиционирующих формул клиента.
Тире в русском — нормальная пунктуация, правило «no em dashes» не применяем.

## Чего на сайте быть не должно

- Ставок партнёрского и дизайнерского вознаграждения — прямое указание клиента.
  Во внутренних документах они есть, в публичном тексте их нет.
- Утверждений о хранении видеоархива за пределами России: формулировка из старой
  презентации, клиент её отозвал. Разбор — `audit/06-legal-checklist.md`.
- Фотографий объектов без письменного разрешения владельца.

## Где что лежит

| Папка | Что |
|---|---|
| `site/` | Приложение Next.js 16, App Router, `output: export` |
| `tz-site/` | ТЗ, 24 документа. Карта — `00 — MOC`, инварианты — `19` |
| `tz-site/prototype/` | Прототип: источник всего текста |
| `audit/` | Одиннадцать разборов: конкуренты, юридический чек-лист, замер выдачи |
| `strategy/` | 78 «рычагов» — вопросов, на которые отвечает сайт |
| `site-foundation/` | Редиректы, выгрузка, реестр графики, список к заполнению |
| `materials/` | Исходные материалы клиента |
| `tools/` | Выгрузка, приёмки, генераторы, упаковщики |

## Работа вдвоём

Проект ведут двое, через разных агентов. Отсюда:

- ветка на задачу, pull request на слияние, `npm run check` зелёный до слияния;
- решения, изменившие правила, записываются в `tz-site/` тем же коммитом, что и код.
  Иначе второй участник унаследует поведение без причины и откатит его как ошибку;
- `CLAUDE.md` и `AGENTS.md` меняются вместе.
