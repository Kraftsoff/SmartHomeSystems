## D. Разработка (Этап 1, после A4)

| # | Задача | Приёмка |
|---|---|---|
| D1 | SSR/SSG: контент и JSON-LD в HTML **до** выполнения JS | `curl` страницы содержит текст ответа и разметку |
| D2 | Постраничная мета: свои `title`/`description`/`canonical`/один H1 | множество title = множеству URL. **В прототипе закрыто:** 103 уникальных title, 103 description, 103 canonical на 103 маршрута, ни одного пустого. Переносится в SSR как есть |
| D3 | 75 рычагов в полные страницы `/answers/{slug}` по шаблону | каждая проходит пункты шаблона, текст через `humanizer`/`stop-slop` |
| D4 | Картинки из base64 в файлы, WebP/AVIF, `lazy` | HTML без изображений; Core Web Vitals «good» |
| D5 | 301-редиректы по готовой карте: **178 правил**, из них 133 на легаси-домены | каждый старый URL → 301 → 200, без цепочек. Зеркало `mimismart.ru` имеет свою транслитерацию и обрабатывается отдельными правилами, не общей склейкой |
| D7 | **Развёрнутую часть ответа выпустить обычной разметкой, а не `<template>`** | В прототипе она лежит в `<template>`, чтобы 75 блоков не раздували дерево одного документа. Замерено: краулер, парсящий сырой HTML, видит все 83 500 знаков этой части (44% текста сайта), а краулер, который рендерит DOM, — ноль. На SSR каждый ответ становится отдельной страницей, и там `<template>` не нужен и вреден: блок должен быть обычным HTML. Приёмка: `grep -c template` на выданной странице ответа = 0, текст таблиц присутствует в отрендеренном DOM |
| D6 | **Каждый кейс — свой URL** `/portfolio/{slug}` с разметкой, а не карточка в общей сетке | Сейчас кейсы живут только в сетке на одной странице: для ИИ-поиска это один документ вместо N извлекаемых. Делать после B1 — на заглушках отдельные URL дадут тонкие страницы, что хуже их отсутствия. Структура карточки уже правильная (боль → задача → что сделали → что изменилось), её достаточно разложить по адресам |

**Почему D1 первый.** Замерено: GPTBot, OAI-SearchBot, PerplexityBot и ClaudeBot **не исполняют
JavaScript** (Vercel/MERJ, 500 млн+ запросов), YandexBot для SPA ненадёжен. Без JS наш прототип
показывает 732 знака текста и 0 видимых страниц. То есть для четырёх из пяти интересующих нас
краулеров сайт сейчас пуст — независимо от качества содержимого.

## E. Вне сайта — крупнейший разрыв со стратегией

Всё построенное находится на сайте. По доказательной базе сильнее всего на цитируемость в
ИИ-поиске влияют **внешние сигналы**: упоминания на YouTube (корреляция 0.737), брендовые
упоминания в вебе (0.664) — против 0.218 у ссылок; 82% цитат приходят на earned media.

Это не задача разработки. Конкретно для российского рынка: YouTube с разборами реального
монтажа, присутствие и отзывы на Яндекс.Картах и Услугах, экспертные материалы на профильных
площадках, участие в отраслевых ветках. Требует бюджета и решения — вынес сюда, чтобы это не
всплыло на запуске.

## F. Приоритет доработки контента — по замеру, а не поровну

Замер выдачи (`../audit/08-serp-baseline.md`) закрыт: **75 запросов из 75, все десять кластеров.**

**Четыре вывода, меняющие план:**

1. **Кластер «Возражения» свободен полностью** — интеграторов в нём нет ни в одном запросе.
   Отвечают Википедия, медиа-страшилки и форумы самодельщиков. Самая дешёвая зона входа.
2. **В «Технологиях» два запроса вообще не имеют русскоязычной выдачи** — «расширять систему со
   временем» и «KNX или Modbus». Движок отвечает англоязычными страницами про коммерческие
   здания. Ниша пустая буквально.
3. **По четырём запросам движок прямо сообщил, что ничего не нашёл:** камин в сценариях,
   слаботочка (принял термин за название ЖК), замена снятого с производства модуля, как стать
   дилером. Это самый чистый сигнал из всех — там нет не только ответа, но и конкурента.
4. **Карта редиректов строилась не на том сайте** — подробности в C8. Перестроена, но полностью
   закрывается только выгрузкой из Вебмастера.

**Порядок публикации.** Сначала тринадцать тем, где спрос подтверждён, а отраслевого ответа нет:
модуль сняли с производства · камин в сценариях · резерв питания и ДГУ · коммерческий объект с
посетителями · слаботочка застройщику · что будет, если компания закроется · vendor lock-in ·
один датчик уронил систему · гарантия: на что и сколько · расширение через год · свой контроллер
против чужого железа · KNX или Modbus для дома в РФ · как стать дилером.

Затем — темы в занятом, но слабом пространстве: сервис после сдачи, сроки по этапам, порог
оправданности DALI, ограничение домофона от УК, питание под электрокарнизы, эскалация тревог для
пожилых, ретрофит после ремонта, диагностика, вентиляция, отказоустойчивость (у Хабра три
позиции, но ответ размазан по комментариям — берётся таблицей «что сломалось → что работает →
срок восстановления»).

Отдельная строка — **децентрализованная архитектура**: мы уже в топ-3 органики, но сводка движка
вытянула из нашей страницы образы вместо цифр. Задача не вытеснить, а переписать своё же под
машинную извлекаемость и не потерять URL при переезде.

В последнюю очередь — четыре страницы, которые скорее наша формулировка, чем спрос (правка
сценариев, координация подрядчиков, щит, диагностика поломки). Полезны внутри воронки доверия,
точками входа не будут.

**Куда не заходить:** «отопление и кондиционирование в одной системе» (отраслевые журналы
отвечают верно), «мультирум: что это» (Википедия), «можно ли взломать умный дом» (выдача честна,
включая интеграторов), «проводной или беспроводной» (конкуренты уже дают конкретику с привязкой
к площади и стадии ремонта — обходить только ценой с обоснованием), «умный дом застройщику»
(ЕРЗ и Коммерсантъ по авторитету не двигаются — заходить только конкретикой сметы и стадий).

**Отдельно:** двадцать два тезиса в текущей выдаче фактически неверны или односторонни
(см. аудит) — это готовые цели, корректная страница вытесняет неверную легче.

133 маршрута · 0 битых · 0 пропусков уровней заголовков · один H1 на страницу · 0 страниц без
хлебных крошек · 0 случайных 404 · 133 уникальных title, description и canonical · 0 ошибок консоли · 0 нарушений
контраста WCAG AA в обеих темах · 0 нарушений доступности по набору правил · CLS 0 ·
нет горизонтального переполнения на 360/390/768/1024/1440 · разметка синхронна с JS и без ·
75 рычагов со своими страницами и поиском · калькулятор состава работ · печатные стили ·
все 75 страниц с развёрнутыми блоками (таблицы отказов, проверочные вопросы) — прямой ответ остаётся
первым абзацем и единственным, что попадает в разметку FAQPage.

**Объём.** Средняя страница ответа — около 1500 знаков против 300–400 в начале: прямой ответ,
таблица, разбор неверного тезиса из выдачи и вопросы, которые стоит задать подрядчику. Всего
69 таблиц. Развёрнутая часть лежит в `<template>`: в исходнике HTML она есть (краулер без
JavaScript видит все 69 таблиц), в дерево рендера списка не попадает — узлов 2071 вместо 4090.

**Честно про производительность.** Перевод в `<template>` вдвое сократил число узлов, но время
до интерактивности не изменилось: 959 мс против 971 при четырёхкратном замедлении процессора.
Это подтверждает прежний замер — упирается в разбор одного документа на 880 КБ, а не в дерево и
не в логику. В продакшене этой проблемы нет по построению: каждый ответ становится отдельной
страницей на SSR (D1, D3), то есть документом с одним блоком вместо семидесяти пяти.

**Что усилено по результатам замера.** Пять ответов, где движок вытянул из наших же страниц
образы вместо инженерии, получили машиночитаемую структуру: таблица «что отказало → что
перестаёт работать → что продолжает → управление руками», разбор четырёх ситуаций «модуль сняли
с производства», таблица «что закладывать сейчас → что позволит потом → если не заложено», список
из пяти документов, без которых объект не переживает смену подрядчика, и разграничение трёх
понятий, которые в выдаче называют одним словом. Каждая страница выросла с ~300–400 до 1400–2300 знаков, и в каждой отдельным блоком разобран
тезис из выдачи, который фактически неверен.

**Исправлено и у себя.** Ответ про сроки монтажа нёс ровно ту односторонность, которую замер
вменяет выдаче: «кабель идёт параллельно ремонту и отдельного времени не требует». Верно для
одного этапа из пяти. Переписан сам прямой ответ, а не только развёрнутый блок — краулеры читают
именно его.

**Проверки идут в CI.** `.github/workflows/checks.yml` гоняет оба инструмента на каждый
pull request, затрагивающий прототип, инструменты или документы, и на push в main. Первый же
прогон окупился: он поймал аварию в проверке языка, которую локальный обход не видел, потому
что решал «прошло или нет» по наличию значка в выводе, а у аварии его нет.

**Как проверить состояние самому.** `node tools/accept.mjs` — один прогон вместо шести скриптов:
обход всех маршрутов, битые страницы, уровни заголовков, H1, крошки, случайные 404, видимые
сырые теги, уникальность title/description/canonical, ошибки консоли, доступность по набору
правил, контраст WCAG AA в обеих темах, горизонтальное переполнение на пяти ширинах, валидность
разметки и её согласие с DOM, отсутствие заглушек в структурированных данных, дублирование
текста между страницами, масштаб 200%, размер целей нажатия, клавиатурный фокус, уважение к
настройке «уменьшить движение», а также то, что видит краулер без JavaScript. Плюс поведение:
поиск, калькулятор, форма с согласием и модель дома.

Второй инструмент — `node tools/lint-text.mjs <файл>` — проверяет стандарт языка из CLAUDE.md
по сайту и по всем документам проекта: канцелярит, филлеры, декларации вместо фактов и
сравнительное превосходство о себе без критерия (ФЗ-135 ст. 14.2/14.3). Возвращает код 1 при
нарушениях — годится для CI. Раньше проверки жили во временной папке сессии и исчезали вместе с
контейнером.

**Чего прототип не может по своей природе:** быть видимым краулерам без JS, отдавать постраничную
мета с сервера и кешировать ресурсы отдельно от документа. Это D1–D4.
