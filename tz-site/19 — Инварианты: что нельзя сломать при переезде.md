# 19 — Инварианты: что нельзя сломать при переезде

← [[00 — MOC (карта ТЗ)]] · технические требования — [[04 — Технические требования]]

## Зачем этот файл

Семьдесят четыре проверки живут в `tools/accept.mjs`, и он работает против **прототипа** —
одного HTML-файла. При переезде на боевой стек инструмент перестанет запускаться, а вместе с ним
исчезнут и правила, которых он держал. Здесь они записаны как требования, независимые от стека.

У большинства указана причина. Правило без причины выбрасывают первым, а каждое из этих появилось
после конкретного отказа — своего или увиденного в чужой выдаче.

## Разметка

| Требование | Почему |
|---|---|
| Прямой ответ в `FAQPage` — только текст, без разметки внутри | разметка внутри ответа означает, что развёрнутый блок утёк в то, что читает краулер |
| **Ответ с непроверенным в прямой части в разметку не идёт целиком** | одиннадцать записей отдавали машине «от 2–3 млн ₽ ⚠️ порог уточняется». Вырезать пометку нельзя: тогда неподтверждённое число уходит как утверждённое |
| Число записей `FAQPage` = числу карточек без пометок | иначе разметка расходится с содержимым молча |
| Разметка совпадает с DOM с исполнением JS и без | собранная скриптом разметка не существует для краулеров, не исполняющих JS |
| `Article` на странице ответа, не `QAPage` | `QAPage` — для страниц, где ответы присылают пользователи; у нас один авторский ответ |
| `author` отсутствует, пока имя не подтверждено | заглушка в структурированных данных попадёт в индекс как имя автора |
| В `Organization` только проверяемые поля | непроверенное в разметке цитируется как факт о компании |

## Тексты

| Требование | Почему |
|---|---|
| Заголовок страницы — вопрос в формулировке пользователя | точка входа сопоставляется с запросом. К подзаголовкам внутри ответа не относится |
| Прямой ответ — первые 1–2 предложения | извлекается начало |
| **Вопрос «да/нет» получает «да» или «нет» первым словом** | девять из пятнадцати не давали, включая вопрос про взлом, где уход читается особенно плохо |
| Ни одного дословного повтора предложения между страницами | вес делится, машина выбирает между копиями |
| Сходство любых двух страниц ниже 0.35 по четырёхсловным окнам | пересказ своими словами — тот же отказ, поиском по предложениям не виден |
| **Текст не обещает того, чего на странице нет** | два ответа обещали «демо на этой странице», а модель дома стоит только на главной |
| **Числовое обещание совпадает с длиной списка** | «пять стадий» в прямом ответе против «шести шагов» в блоке под ним |
| Утверждение о демо совпадает с тем, что демо делает | текст говорил «перекрывает воду», а состояния воды в модели нет вовсе |
| Сравнительное превосходство о себе — только с критерием и источником | ст. 14.2 и 14.3 ФЗ-135, штраф от 100 000 ₽ |

## Адреса и переезд

| Требование | Почему |
|---|---|
| Каждый маршрут есть в `sitemap.xml`, каждый URL карты существует | URL без страницы даёт ошибку сканирования и тратит бюджет обхода |
| **Путь, который отдаёт 410, не закрыт в `robots.txt`** | закрытый от обхода бот не запросит, 410 не увидит, адрес останется в индексе |
| `/articles/` легаси ведётся адресно, без склейки в раздел | там единственная страница, стоящая в органике третьей |
| Зеркало `mimismart.ru` — своими правилами | у доменов расходится транслитерация: `ventilyatsiya` против `ventilyacziya.html` |
| Цель редиректа существует | редирект в никуда хуже отсутствующего |
| Один `title`, `description`, `canonical` на маршрут | дубли делят вес |

## Доступность и поведение

| Требование | Почему |
|---|---|
| Контраст WCAG AA в обеих темах | ночная тема ломалась отдельно от дневной |
| Фокус видим на каждом элементе обхода табом | правиловая проверка этого не покрывает |
| **Ссылка пропуска навигации видна на прокрученной странице** | при `position:absolute` она уезжала за верхний край |
| Нет горизонтальной прокрутки на 360px и при масштабе 200% и 400% | WCAG 1.4.10; прокрутка внутри обёртки таблицы допустима |
| `prefers-reduced-motion` отключает переходы и не оставляет контент полупрозрачным | иначе часть текста просто не видна |
| Таблицы: подпись колонки у каждой ячейки | скринридер иначе читает числа без смысла |
| **Проходимость проверяется по всему отрезку хода, а не по его концу** | точечная проверка стену не держит: по обе стороны перегородки пол, и один быстрый `pointermove` переносит жителя в соседнюю комнату. Шаг выборки мельче самой тонкой перегородки на плане (измерено: 4.8 px) |
| **При отказе в движении прошлая позиция не обновляется** | иначе запрет прячет след, а человек всё равно телепортируется и следующий шаг делает уже из-за стены. Именно это правило заставляет обводить курсор через проём |
| Маска плана читается один раз в массив; прямоугольники объектов — один раз на событие | трассировка делает десятки проб на движение мыши; поштучный `getImageData` съедает кадр |
| В машине нет шильдиков, эмблем и надписей | узнаваемая марка на иллюстрации — чужой товарный знак в нашем материале |

## Согласие и закон

| Требование | Почему |
|---|---|
| Аналитика не стартует до явного согласия | ст. 9 ФЗ-152 |
| **Переходы по сайту без ответа на баннер согласием не считаются** | позиция РКН: «продолжая пользоваться сайтом» — не согласие |
| Отказ сохраняется и переживает переход | решение, которое переспрашивают до нужного ответа, решением не является |
| Форма не отправляется без отметки согласия | ст. 9 ФЗ-152 |
| Сведения об исполнителе в подвале — на всех страницах | п. 1 ст. 9 ЗоЗПП, до 10 000 ₽ |

## Как проверять на новом стеке

Проверки из `accept.mjs` переносимы: они работают с отрендеренной страницей через браузер, а не
с исходником прототипа. Менять придётся способ получения списка маршрутов — сейчас он собирается
обходом ссылок в одном документе, на боевом стеке возьмётся из роутера или `sitemap.xml`.

Три инструмента переносить не нужно, они работают с файлами: `lint-text.mjs` (стандарт языка),
`check-docs-sync.mjs` (числа в документах против прототипа), `check-redirect-coverage.mjs`
(карта против выгрузки из Вебмастера).

**Главное правило про сами проверки.** Каждый гейт проверять на способность падать, а не только
на зелёный цвет. За одну сессию семь раз ошибка оказывалась в проверке, а не в сайте: регулярка с
`\b` перед кириллицей не совпадала никогда, клонирование узла ломало учёт скрытых элементов,
подсчёт `<loc>` захватывал пример внутри комментария. Зелёная проверка, которая не умеет падать,
опаснее отсутствующей: она создаёт уверенность.
