# Аудит превью MiMiSmart — находки (SEO/AEO · Frontend · Контент/Маркетинг)

Дата: 2026-06-29. Основано на 5 собранных страницах (`/`, `/controller`, `/detector`,
`/catalog`, `/portfolio`) + карте маршрутов. Это снимок из браузера, не живой краулинг —
часть выводов (SSR, robots, schema) требует проверки raw-HTML снаружи.

Степень: 🔴 критично · 🟠 важно · 🟡 средне.

---

## 1. SEO / AEO (под ИИ-поиск) — главная зона риска

- 🔴 **Нет meta description ни на одной странице.** `<meta name="description">` пуст везде.
  Для ИИ-поиска и сниппетов это потеря управляемого ответа.
- 🔴 **Title неинформативны.** Это просто названия разделов: «MiMiSmart», «Контроллеры»,
  «Датчики», «Каталог», «Проекты». Нет формулы «вопрос/выгода + бренд + гео».
- 🔴 **Нет Open Graph / Twitter мета** (`og:title`, `og:description`, `og:image`) — плохие
  превью при шеринге и для части ИИ-агрегаторов.
- 🔴 **Нет H1.** Главная и внутренние стартуют с H2; единого H1 на страницу нет —
  ломается семантика, по которой ИИ строит ответ.
- 🟠 **Нет canonical.** При наличии дублей slug (см. ниже) это риск каннибализации.
- 🟠 **Не подтверждены `sitemap.xml`, `robots.txt`, `/llms.txt`, JSON-LD (Schema.org).**
  В снимке не видно структурированных данных (`Organization`, `Product`, `FAQPage`,
  `Offer`, `LocalBusiness`). Для нашей AEO-стратегии это обязательный слой — проверить.
- 🟠 **Не подтверждён SSR/выдача контента в raw-HTML.** Стек — Next.js (App Router,
  `/_next/...`); в сохранённом DOM текст есть, но нужно проверить `view-source`, что тот же
  контент уходит краулеру до гидрации (иначе ИИ его не увидит).

## 2. Контент / маркетинг — против нашей AEO-философии («ноль воды, конкретика»)

- 🔴 **Тестовые заглушки в проде:** на главной блок статей — «Полезная статья / Тестовое
  описание» (×2); карточки решений обрываются на «…создаём умную квартиру...».
- 🔴 **Пустой портфолио/кейсы.** `/portfolio` и блок «Кейсы» на главной — только фильтры
  (Все/Освещение/Климат/…), **ни одного кейса**. Кейсы = ядро доказательной базы для ИИ.
- 🔴 **Нет цен и обоснования цены.** Пункт «Цены» в меню есть, но контента/маршрута нет.
  Это прямо противоречит стратегии (цена + почему столько + почему не дешевле).
- 🔴 **Пустой каталог.** `/catalog` и `/controller` показывают 1 товар (CUARM5M) с одной
  строкой описания. Нет характеристик, цен, сравнения.
- 🟠 **Дублирование/ошибка копирайта:** `/catalog` выводит описание контроллеров
  («Это мозг системы…»), хотя это каталог — текст не на своём месте.
- 🟠 **Тексты обзорные, без конкретики «для кого / сколько / почему мы».** Хорошие
  формулировки есть (датчики: «Тревога вовремя», «Вода перекрыта»; щит автоматизации —
  живое описание), но нет цифр, условий, сравнений — то, что цитирует ИИ.
- 🟡 **Заголовки не в форме вопроса** — ни один не повторяет реальный запрос пользователя.

## 3. Доверие / E-E-A-T (критично, т.к. ИИ оценивает достоверность)

- 🔴 **Телефон-заглушка:** `+7 (4012) 234-34-34`. Код 4012 — Калининград, при московском
  адресе; номер выглядит как филлер. Несоответствие гео = удар по доверию.
- 🟠 **Почта `MiMiSmart@mail.ru`** — бесплатный ящик, не корпоративный домен. Для бренда
  с «5000+ объектов» это диссонанс.
- 🟠 **Непроверяемые заявления без пруфов:** «5000+ объектов», «20 представительств по
  всему Миру», «Пожизненная гарантия», «самые миниатюрные датчики в мире», рейтинг «4.9»
  (без ссылки на агрегатор). Нужны доказательства/источники — иначе ИИ это обесценит.
- 🟡 **Адрес `Москва, Новоданиловская наб., 6к1`** — совпадает с публичными данными ✅
  (единственный согласованный контакт).
- 🟡 Разделы «Отзывы», «Сертификаты» есть в футере → проверить, наполнены ли (доказательная база).

## 4. Frontend / тех

- ℹ️ **Стек:** Next.js (App Router), кастомные шрифты (Helvetica + woff2), CSS-чанки.
  Признаки полноценного приложения: корзина, избранное, поиск, аккаунт, версия «1.1.91»,
  тариф «Free», `/vendors`, `/settings` → это не просто лендинг, а сайт + магазин/кабинет.
- 🟠 **Опечатки в URL-slug** (уйдут в индекс и ссылки): `/lightning` (→ lighting),
  `/himidity` (→ humidity), `/detector/infared-sensor` (→ infrared), `/solutions-appartments`
  (→ apartments). Исправлять до индексации, иначе позже — редиректы.
- 🟡 **`/ai`** — отдельный маршрут неизвестного назначения. Если это ИИ-ассистент/поиск —
  важно для нашей стратегии, надо изучить.
- 🟡 Повтор навигации (верх + повторный блок) в DOM — проверить, не дублируется ли контент.

## 5. Информационная архитектура — сильная сторона

- ✅ Footer = развёрнутая, логичная таксономия (Шторы / Освещение / Климат / Мультимедиа /
  Безопасность / Электрика / Оборудование / Датчики / Готовые решения). Хороший скелет IA,
  на него ляжет система «60 рычагов».
- ✅ Сегментация решений (квартира / дом / офис / ЖК) уже заложена — совпадает с персонами.

## Приоритеты (черновик, до полного сбора)
1. 🔴 Мета-слой: title/description/OG/canonical + H1 на каждую страницу (шаблонизировать).
2. 🔴 Убрать тестовые заглушки; наполнить кейсы и каталог реальными данными.
3. 🔴 Раздел «Цены» с обоснованием (ядро AEO-стратегии).
4. 🔴 Привести контакты к реальным (телефон/почта/домен) — доверие.
5. 🟠 Schema.org/JSON-LD + sitemap + robots + llms.txt; проверить SSR.
6. 🟠 Исправить slug-опечатки до индексации.
7. 🟠 Перевести контент в формат «рычагов»: вопрос → прямой ответ → для кого → сколько/почему → почему мы.

## Что нужно дослать для полного аудита
`/news`, `/about`, `/contacts`, `/solutions*`, страница цен, индивидуальные страницы функций,
`/admin`, `/ai`, карточки товара. Идеально — ещё и raw `view-source` главной (для проверки SSR/schema).
