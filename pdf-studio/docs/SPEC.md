# PDF Studio — Техническое задание (ТЗ)

> Самостоятельный проект. Не связан с Совой, Мимисмарт и notaOS.
> Версия документа: 1.0 · Целевая платформа: Windows 10/11 (x64).

## 1. Видение и позиционирование

**PDF Studio** — лёгкий, быстрый и «комфортный» PDF-редактор для Windows,
работающий полностью офлайн и без подписки.

### 1.1. Анализ рынка (2026)

| Продукт | Модель | Сильные стороны | Слабые стороны |
| --- | --- | --- | --- |
| **Adobe Acrobat Pro** | Подписка $130–240/год | Эталон: OCR, редакция, э-подпись, формы, облако, аудит | Дорого, тяжёлый, избыточен для большинства |
| **Foxit PDF Editor** | Подписка/лицензия | Ribbon-UI как в Office, ~90% функций Adobe, легче | Платный, местами перегружен |
| **PDF-XChange Editor** | Разовая покупка | Очень плотный функционал, OCR, штампы, измерения, JS | Устаревший UI, кривая обучения |
| **PDFgear** | Бесплатно | Полное редактирование, OCR, конвертация, AI-чат | Проприетарный, телеметрия, онлайн-функции |
| **Wondershare PDFelement** | Подписка/лицензия | Дружелюбный UI, AI-ассистент | Платный, апселлы |

**Вывод.** Рынок делится на дорогой энтерпрайз (Adobe/Foxit) и «бесплатные, но
проприетарные с облаком/AI» (PDFgear/PDFelement). Свободная ниша — **быстрый,
приватный (offline-first), без подписки инструмент с приятным UX**, закрывающий
80% ежедневных задач: просмотр, аннотации, управление страницами, сборка/разбор,
подпись изображением, экспорт.

### 1.2. Ключевые функции, которые ждут пользователи

По результатам обзоров (PCWorld, Nitro, Guideflow, Drawboard):

1. Прямое редактирование текста.
2. Богатые аннотации: выделение, подчёркивание, зачёркивание, стикеры-заметки,
   рисование от руки, фигуры, стрелки.
3. OCR (распознавание текста в сканах).
4. Настоящая редакция (redaction) — необратимое удаление содержимого.
5. Э-подпись (набранная / нарисованная / изображение).
6. Управление страницами: поворот, перестановка, дублирование, удаление, слияние.
7. Заполнение форм.
8. Конвертация (в/из Office, изображения).
9. Пакетная обработка.

### Релиз 1.1 — Импорт HTML и презентаций (реализовано)

Запрошено пользователем: в HTML часто оформлены презентации, которые хочется
разметить, что-то нарисовать и подредактировать.

- **M** ✅ Импорт локального `.html`-файла или URL: страница рендерится в
  скрытом sandboxed-окне Chromium и конвертируется в PDF (`printToPDF`).
- **M** ✅ Автоопределение слайд-презентаций (reveal.js и совместимые: наличие
  `window.Reveal` или `.reveal`/`.slides`) — подставляется параметр
  `?print-pdf`, при котором такие фреймворки сами раскладывают «один слайд =
  одна страница» книжной/альбомной ориентации.
- **M** ✅ После конвертации документ открывается в обычном PDF-редакторе —
  доступны все существующие инструменты: аннотации, рисование, штампы,
  забелка+текст (правка контента), извлечение/экспорт.

**Архитектурное решение.** Рассмотрены варианты: (а) HTML→PDF→редактор,
(б) живой просмотр с рисованием поверх DOM, (в) прямое редактирование HTML
через contentEditable. Выбран (а): переиспользует весь существующий слой
аннотаций/редактирования без дублирования кода, надёжен для произвольных
страниц с произвольным JS, и не требует синхронизации координат аннотаций с
живым, перетекающим/скроллящимся DOM. Живое редактирование HTML — кандидат на
будущий релиз, если понадобится (см. «Возможные развития» ниже).

**Безопасность.** Окно конвертации без Node-интеграции, с `sandbox: true` и
`contextIsolation: true` — веб-страница выполняется в том же доверительном
периметре, что и обычная вкладка браузера, и уничтожается сразу после
конвертации.

### Возможные развития (не запланированы)

- Живое редактирование исходного HTML (contentEditable) для тонкой правки
  текста/раскладки до конвертации в PDF.
- OCR (tesseract.js), опциональное шифрование через qpdf.

## Ограничения реализации

Стек `pdf-lib` (чистый JS, offline) не поддерживает часть возможностей штатно;
для честности они реализованы через альтернативы или отложены:

- **Шифрование паролем** — `pdf-lib` умеет читать зашифрованные PDF
  (`ignoreEncryption`), но не записывать зашифрованные. Полноценная парольная
  защита требует внешней зависимости (например, `qpdf`), что нарушило бы
  offline/лёгкость. Отложено; кандидат — опциональная интеграция qpdf.
- **Inline-редактирование текста** — прямое изменение существующего текстового
  слоя PDF требует разбора и пересборки content-stream и работы со шрифтами.
  Вместо этого предложены «Забелка + текст» (закрыть и написать заново) и
  редакция. Полноценный редактор текста — отдельный крупный этап.
- **Истинная редакция** реализована через растрирование затронутой страницы:
  надёжно удаляет содержимое, но страница теряет текстовый слой (становится
  изображением). Это осознанный компромисс, типичный для лёгких редакторов.

## 4. Нефункциональные требования

- **Производительность:** плавный рендер страниц (pdf.js), ленивая отрисовка
  миниатюр; открытие файла до ~50 МБ без заметных задержек.
- **Приватность:** офлайн-first, без телеметрии и обязательных сетевых вызовов.
- **Надёжность:** неизменяемые снимки документа → предсказуемые undo/redo.
- **Безопасность:** `contextIsolation` включён, `nodeIntegration` выключен,
  строгий CSP в renderer, файловый I/O только в main-процессе.
- **UX:** тёмная и светлая темы, горячие клавиши, drag&drop, отзывчивый UI.
- **Совместимость:** Windows 10/11 x64; код кроссплатформенно собирается.

## 5. Архитектура

```
src/
  shared/      IPC-контракт (каналы и типы) для main и renderer
  main/        Главный процесс: окно, меню, диалоги, файловый I/O, недавние файлы
  preload/     contextBridge — типизированный безопасный API
  renderer/    React-приложение
    lib/         pdf.js (рендер), pdf-lib (правки), модель аннотаций
    hooks/       useDocument (история), usePdfDoc (загрузка), useTheme
    components/  Toolbar, Sidebar, PdfCanvas, AnnotationLayer, FindBar, StatusBar, Welcome
```

**Принципы.** Документ — стек неизменяемых снимков (`bytes` + аннотации).
Структурные правки идут через pdf-lib и порождают новые `bytes`. Аннотации —
отдельный слой в нормализованных координатах (0..1), впекаются в PDF при
сохранении. Весь файловый доступ изолирован в main-процессе.
