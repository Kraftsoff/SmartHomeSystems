## Что это за проект и чем он отличается

Сайт проектируется **под ИИ-поиск**, а не под классическое SEO. Точки входа — Google
SGE, Яндекс Нейро, ChatGPT. Из этого следует всё остальное устройство:

- у каждого ответа **свой адрес**, заголовок в форме вопроса и прямой ответ первым
  абзацем — так, чтобы машина могла извлечь ответ, не разбирая страницу;
- **весь текст лежит в HTML до исполнения скриптов**: замерено, что GPTBot,
  OAI-SearchBot, PerplexityBot и ClaudeBot JavaScript не исполняют;
- **ни одной выдуманной цифры.** Всё непроверенное помечается `⚠️` прямо в тексте
  и попадает в собираемый список `site-foundation/fill-list.md`. Сейчас таких
  пометок 84. Убрать пометку, не получив данные, нельзя: неподтверждённое уйдёт
  машине как факт и вернётся к клиенту вопросом, откуда цифра.

Ядро содержимого — **78 «рычагов»**: реальный поисковый запрос → прямой ответ → как
делается → в каких случаях → сколько стоит и почему → почему мы → возражения.
Разбор в `strategy/`.

## Двенадцать вещей, которые стоит знать до первой правки

1. **Текст правится в прототипе**, `tz-site/prototype/mimismart-v5.html`, а не в
   `site/`. Подробности в README. Из-за этого здесь уже терялась работа.

2. **Приёмок две и предмета два.** `accept.mjs` проверяет прототип, `accept-site.mjs` —
   собранные файлы. Это не две версии одного.

3. **Клиентские компоненты не попадают в HTML.** Всё, что нарисовано в браузере, для
   ИИ-поиска не существует. Из-за этого визуальный слой однажды был на двух страницах
   из 141: диаграммы и схемы рисовались клиентом, и в разметке их не было. Новые
   кадры отдаются сервером строкой (`site/app/components/Shot.tsx`).

4. **Разрезать готовый HTML на две части нельзя.** Половинки, разложенные по двум
   контейнерам, браузер достраивает по-своему, разметка расходится с серверной, и
   React роняет гидратацию (ошибка 418). Вставка идёт строкой в ту же разметку.

5. **Клиентский компонент не должен импортировать `@/lib/content`** — за собой он
   утянет весь файл содержимого в бандл. Однажды это дало рост скриптов с 260 до
   317 КБ. Данные передаются пропсами.

6. **Витрина отдаётся из подпапки**, и корень путей переставляется отдельным шагом
   (`tools/rebase-links.mjs`). Он правит HTML, а также точечно — адреса файлов внутри
   собранных скриптов и стилей. Дважды на этом обожглись: сначала не переставлялся
   `srcset` (битыми были все пятнадцать кадров при рабочем `src` рядом), потом путь
   к плану дома, зашитый строкой в бандл и в CSS. Приёмка этого поймать не может:
   она гоняется по сборке для боевого корня. Проверку шаг делает сам.

7. **Тёмная тема — основная** и приходит атрибутом в разметке. Системная настройка
   её не отменяет: вся графика бренда снята на чёрном. Решение клиента 1 сентября,
   разбор в `tz-site/07`.

8. **Приёмка обязана уметь падать.** Несколько условий когда-то не могли: мерили
   контейнер вместо переполняющего его содержимого, считали класс, который со страниц
   исчез, принимали любой значок вместо нужной пометки. Стенд `tools/mutate.mjs`
   существует ровно для этого — он подсаживает дефект и требует, чтобы приёмка его
   назвала. Добавили условие — добавьте туда мутацию.

9. **Проверка должна перечислять то, что осталось, а не считать сделанное.**
   «Правок 7242» не доказывает ничего; «корневых адресов мимо корня не осталось» —
   доказывает.

10. **Числа в документах устаревают молча.** `tools/check-docs-sync.mjs` сверяет их
    с прототипом и падает при расхождении. Один раз работа шла по устаревшей картине.

11. **Кириллица и `\b` в регулярных выражениях не дружат.** Обжигались дважды,
    в том числе в собственном измерительном скрипте.

12. **`str.replace` молча ничего не делает**, если якорь не совпал. В этом проекте
    так трижды терялись правки. Проверяйте, что замена состоялась.

## Как этот репозиторий появился и что с ним делать

Сайт разрабатывался веткой в репозитории `Kraftsoff/SmartHomeSystems`, где рядом
живут другие проекты. В отдельное дерево он выделяется командой:

```bash
node tools/pack-handover.mjs [куда]
```

Она берёт список файлов у git — поэтому в пакет не попадает ни сборка, ни
`node_modules`, ни временное, — отбрасывает резервные архивы и вендорные скиллы
маркетинга и складывает результат тремя способами: дерево, `git bundle` и zip.

**Развернуть из bundle** (несёт историю, разворачивается обычным клоном):

```bash
git clone mimismart-site.bundle mimismart-site
cd mimismart-site
npm run setup && npm run check
```

**Поднять на GitHub** — репозиторий создаёт владелец аккаунта, дальше:

```bash
git remote add origin git@github.com:ВЛАДЕЛЕЦ/mimismart-site.git
git push -u origin main
```

CI поднимется сам: `.github/workflows/checks.yml` едет в пакете и требует только
Node 22 — ни секретов, ни внешних служб.

**История разработки осталась в исходном репозитории**, в pull request #1. Там же
причины решений: почему тёмная тема, почему приёмок две, почему текст правится
в прототипе. Пакет несёт один коммит — заводить чистую историю проще, чем тащить
344 коммита вперемешку с чужими проектами.

## Что делать дальше

По убыванию влияния.

### 1. Домен и идентификация через ЕСИА — блокирует всё

С 1 сентября 2026 по 569-ФЗ без идентификации владельца домена через ЕСИА нельзя
менять NS-записи, продлевать домены и передавать их между регистраторами. Пока это
не сделано, переезд и все 194 редиректа заблокированы, а `SITE` остаётся заглушкой.
Задача клиента, не разработки. Разбор — `tz-site/16`.

### 2. Целостность бренда

По брендовому запросу ИИ выдаёт рядом с отзывами текст, отрицающий российское
производство. У бренда пять доменов, два отдают одинаковый заголовок. Пока это не
разведено, содержимое сайта на брендовый запрос не влияет. Замер — `audit/08-serp-baseline.md`,
план сведения — `site-foundation/redirects.md`, часть C.

### 3. Визуальный слой

Кадр есть на 21 странице из 141. Фотографий сданных объектов нет ни одной — три
карточки в кейсах остаются шаблонами и помечены как шаблоны. Что нужно от клиента,
перечислено в аудите; анкета под кейсы — `audit/11-anketa-keysa.md`.

### 4. Первый экран: тур по дому

Решение клиента: тур живёт **отдельной страницей** `/tour/`, на главной — плитка-постер
со ссылкой, без автозапуска. Заказчик заходит на сайт не один раз, и анимация на пути
к ответу — налог на постоянного посетителя. ТЗ и раскадровка — `tz-site/22` и
`tz-site/assets/hero-storyboard.html`. Рендеры не начинаются, пока клиент не ответит
на пять вопросов из раскадровки: переснять одну остановку значит переснять оба стыка
с соседними.

### 5. Собираемый список

`site-foundation/fill-list.md` — 84 пометки с указанием мест. Реквизиты юрлица,
гарантийный талон под бессрочный срок, тарифы обслуживания, складской запас. Каждая
закрытая пометка возвращает запись в разметку `FAQPage`: сейчас туда не попадают
12 ответов из 78 именно потому, что в них стоит непроверенное.

## Что заблокировано и на ком

| Что | На ком | Почему стоит |
|---|---|---|
| Идентификация домена через ЕСИА | клиент | без неё нельзя менять NS-записи |
| Реквизиты юрлица | клиент | в подвале и в разметке организации стоят пометки |
| Фотографии объектов и производства | клиент | нужно письменное разрешение владельца объекта |
| Пять решений по раскадровке тура | клиент | рендеры без них переделываются целиком |
| Какая партнёрская схема действует | клиент | в трёх присланных презентациях три разных процента |
| Боевой домен | клиент | константа `SITE` — заглушка |

Отдельно: **ставки партнёрского и дизайнерского вознаграждения на сайт не выносятся**
по прямому указанию клиента. Во внутренних документах они есть, в публичном тексте
их быть не должно.

## Что я бы сделал в первый день

1. `npm run setup && npm run doctor && npm run check` — убедиться, что все три
   проверки зелёные на нетронутом дереве. Это ваша точка отсчёта.
2. Прочитать `tz-site/19` целиком.
3. Открыть `site-foundation/fill-list.md` и понять, сколько содержимого ждёт клиента.
4. Поменять что-нибудь заметное в прототипе, прогнать `npm run build && npm run check:site`
   и увидеть, как правка доезжает до готового файла. Конвейер после этого понятен
   целиком.
