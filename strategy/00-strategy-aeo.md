# Стратегия сайта MiMiSmart: оптимизация под ИИ-поиск (AEO/GEO)

> Раздел 0 ТЗ. Объясняет «почему так» для всех остальных разделов.
> Принцип короткий: сайт = база ответов для нейросети, а не витрина текста для человека.

## 1. Парадигма: от SEO к AEO/GEO
Классический поиск отдавал 10 синих ссылок — выигрывал тот, кто «накрутил» трафик и
объём текста. ИИ-поиск (Google AI Overviews/SGE, Яндекс Нейро, ChatGPT-search, Perplexity)
делает иначе:
- читает сайты, извлекает **факты**, синтезирует **один ответ** под конкретного пользователя;
- генеричный, «водянистый», шаблонно-сгенерированный контент отсекается на первом проходе
  (он не добавляет новых фактов → не цитируется);
- выигрывает источник с **уникальной, проверяемой, структурированной фактурой**, которую
  удобно процитировать.

**Вывод:** наша задача — стать источником, который ИИ цитирует как авторитет по «умному дому»,
а не ещё одним инфо-сайтом, который ИИ игнорирует.

## 2. Что ИИ ищет на странице (и что мы обязаны дать)
| ИИ ищет | Мы даём |
|---|---|
| Прямой ответ на запрос | 1–2 предложения в начале блока, без воды |
| Конкретные числа | цены, сроки, м², кол-во проектов, гарантия — цифрами |
| «Для кого» | явная привязка к персоне/сценарию |
| Доказательства | своё производство, опыт с 2004, свои контроллеры, кейсы |
| Сравнения | честные таблицы «мы vs альтернатива» |
| Условия/ограничения | в каких случаях подходит, а в каких — нет |
| Структуру | заголовки-вопросы, списки, таблицы, FAQ-разметка |

## 3. Жёсткие правила контента (стандарт качества)
1. **Заголовок = вопрос пользователя.** Как он реально пишет в поиск/чат.
2. **Первый абзац = прямой ответ.** Машина должна процитировать его целиком.
3. **Факт > прилагательное.** Не «высокое качество», а «своё производство контроллеров
   с 2004 г., N реализованных проектов».
4. **Цена всегда обоснована.** Любая цифра цены сопровождается «из чего складывается» и
   «почему дешевле — это риск».
5. **Каждый блок отвечает на 5:** что / для кого / в каких случаях / сколько и почему / почему мы.
6. **Никакой воды и самоповторов.** Если предложение не добавляет факта — удалить.
7. **Запрет на выдумку.** Нет данных — ставим `[ФАКТ: уточнить]`, не сочиняем.

## 4. Техническая упаковка под ИИ (требования к разработчикам)
- **Schema.org / JSON-LD:** `Organization`, `Product`, `Service`, `FAQPage`, `HowTo`,
  `BreadcrumbList`, `Review`/`AggregateRating`, `Offer` с ценой.
- **SSR/SSG** (сайт на Vercel — вероятно Next.js): контент должен отдаваться в HTML без JS,
  иначе ИИ-краулер его не увидит. Проверить, что текст в исходном HTML, а не только в клиенте.
- **`/llms.txt`** в корне — карта ключевых страниц/фактов для LLM-краулеров.
- **robots.txt** — НЕ блокировать ИИ-ботов (GPTBot, Google-Extended, OAI-SearchBot, YandexBot,
  PerplexityBot), если цель — попадать в ИИ-ответы. (Решение бизнеса — зафиксировать.)
- **Чистые семантические URL**, хлебные крошки, sitemap.xml.
- **Скорость и Core Web Vitals** — быстрый, лёгкий HTML.
- **Уникальные title/description** в форме «вопрос → ответ».
- **Таблицы и списки** в HTML (не картинками) — ИИ читает текст, не пиксели.

## 5. Архитектура контента сайта
Три слоя:
1. **Витрина (для людей):** главная, страницы решений/сегментов, кейсы, цены, контакты.
2. **База ответов (для ИИ и людей одновременно):** 75 рычагов — по сути большой
   FAQ/Knowledge-base, где каждый рычаг = страница/блок «запрос → решение → почему мы».
3. **Доказательная база:** кейсы с цифрами, страница «о производстве», сертификаты, отзывы.

## 6. Что нужно от клиента, чтобы убрать «воду» (вход для фактуры)
- Реальные **цены / тарифные вилки** по сегментам и подсистемам.
- **Кейсы** (объект, площадь, состав системы, срок, результат) — хотя бы 5–10.
- **Дифференциаторы с пруфами:** что именно своё (контроллеры, ПО, производство), патенты,
  цифры (лет на рынке, кол-во проектов, гео).
- **Выжимка из базы совещаний** — внутренние формулировки, реальные возражения клиентов,
  частые вопросы, «подводные камни», которые вы уже знаете из практики.
- Гарантия, сроки, условия сервиса.
