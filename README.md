# Сайт MiMiSmart

Новый сайт компании, которая разрабатывает, производит и монтирует системы «умный дом».
Заменит пять устаревших доменов: mmsmart.ru, mimismart.ru, mimismart.com,
mmsmart-russia.ru, mimismart-home.ru.

**139 страниц, статическая сборка на Next.js, ноль зависимости от сервера.**
Витрина для просмотра: <https://kraftsoff.github.io/SmartHomeSystems/> — закрыта от
индексации намеренно, боевого домена пока нет.

---

## Начать за десять минут

```bash
npm run setup     # зависимости корня, зависимости сайта, Chromium для приёмки
npm run doctor    # проверит, чего не хватает, и скажет чем ставить
npm run dev       # localhost:3000
```

`npm run setup` качает Chromium (~150 МБ) — он нужен приёмке, без него сайт всё равно
собирается.

## Одно правило, из-за которого ломаются все

**Текст сайта правится не в `site/`.** Единственный источник содержимого —
`tz-site/prototype/mimismart-v5.html`. Оттуда его достаёт выгрузка и кладёт в
`site/lib/content.json`, откуда его берут страницы. Правка прямо в `site/` живёт
до следующей сборки, а потом молча пропадает.

```
tz-site/prototype/mimismart-v5.html     ← правите здесь
        │  npm run content
        ▼
site-foundation/content-export.json     ← промежуточная выгрузка
        │
        ▼
site/lib/content.json                   ← отсюда читают страницы
        │  npm run build
        ▼
site/out/                               ← 139 готовых HTML-файлов
```

Код, вёрстка, компоненты — наоборот, живут только в `site/` и в прототип не
возвращаются. Прототип отвечает за текст, `site/` — за то, как он показан.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сайт на localhost:3000 с горячей перезагрузкой |
| `npm run content` | Перечитать прототип и обновить содержимое |
| `npm run build` | Выгрузка → сборка → чистка. Результат в `site/out/` |
| `npm run check` | Все три проверки подряд: язык, прототип, собранный сайт |
| `npm run check:site` | Только приёмка собранных файлов (~60 с) |
| `npm run assets` | Пережать графику бренда из `site-snapshot` в `site/public` |
| `npm run pack:pages` | Собрать витрину под GitHub Pages (свой корень путей) |
| `npm run doctor` | Что установлено, чего не хватает |

## Проверки

Три независимые, все умеют падать и все гоняются в CI (`.github/workflows/checks.yml`).

- **`tools/lint-all.mjs`** — стандарт языка по всем текстам проекта плюс сверка чисел
  в документах с прототипом. Работает на голом Node, зависимостей не требует.
- **`tools/accept.mjs`** — приёмка прототипа, 42 группы условий.
- **`tools/accept-site.mjs`** — приёмка собранных файлов, тех самых, что уедут на
  хостинг: мета и то, что она нигде не повторяется, разметка против видимого текста, достижимость
  каждой страницы, мёртвые ссылки, вес, контраст в обеих темах, доступность, узкий
  экран, поведение поиска, калькулятора, формы и плана дома. 42 группы условий,
  большинство обходит все 139 страниц.
- **`tools/mutate.mjs`** — стенд проверки проверок: подсаживает 40 известных дефектов
  и требует, чтобы приёмка назвала каждый. Гоняется по ночам, полный прогон дорогой.

**Приёмки две, потому что предмета два.** Прототип и собранный сайт живут параллельно,
пока перенос содержимого не закончен. Это не две версии одного и того же.

## Что где лежит

| Папка | Что внутри |
|---|---|
| `site/` | Приложение на Next.js 16, App Router, `output: export` |
| `tz-site/` | Техзадание, 24 документа. Карта — `00 — MOC` |
| `tz-site/prototype/` | Прототип: источник всего текста сайта |
| `audit/` | Одиннадцать разборов: конкуренты, доказательная база, юридический чек-лист, замер выдачи, голос покупателя |
| `strategy/` | Стратегия AEO и 78 «рычагов» — вопросов, на которые сайт отвечает |
| `site-foundation/` | Карта 301-редиректов (194 правила), выгрузка, реестр графики, список того, что ждёт данных клиента |
| `site-snapshot/` | Снимок действующего сайта: исходники фирменной графики и его CSS, из которого сняты реальные дизайн-токены |
| `tools/` | Выгрузка, приёмки, генераторы, упаковщики |

## С чего начать чтение

1. **`docs/ПЕРЕДАЧА.md`** — состояние дел, что делать дальше, что заблокировано и на ком.
2. **`tz-site/19 — Инварианты`** — что нельзя сломать и на чём уже обжигались.
3. **`tz-site/16 — Что делать дальше`** — сводка для решений.
4. **`CLAUDE.md`** — стандарт содержимого: ни одной выдуманной цифры, заголовки
   вопросами, прямой ответ первым абзацем.

## Как это выкладывается

Сборка статическая, поэтому подойдёт любой хостинг файлов.

- **GitHub Pages:** `npm run pack:pages`, содержимое `site/out` в ветку `gh-pages`.
  Витрина отдаётся из подпапки, поэтому корень путей переставляется отдельным шагом.
- **Netlify:** `npm run pack:netlify`, содержимое `site/out` в ветку `netlify`.
- **Боевой домен:** `SITE_URL=https://домен npm run build`, содержимое `site/out` куда угодно.
  Редиректы отдаёт хостинг, конфиг генерируется из `site-foundation/redirects.md`.
